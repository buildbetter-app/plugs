# Plug event catalog

Plug has one durable event record: a change in the A6 changeset log. A write
produces one gapless revision and one or more ordered event indexes within that
revision. Plugins do not emit free-form events. A plugin can cause another
write, but that write receives its own changeset and causal chain.

The public JSON-RPC methods are `event.list`, `event.subscribe`, and
`event.unsubscribe`. `event.notify` is a server-to-client push frame. The
`event.gap`, `store.restored`, `watch.reset`, and `visibility.lost` entries
below are control records or delivery markers, not arbitrary plugin-defined
event types.

## Durable event types

The `type` field is stable, lower-case, and dotted. A slot transition uses the
slot's verb even when the underlying operation is a patch. `resource` is the
stable record reference (for example `bead/pl-a3f`), while `changed` contains
JSON Pointer paths relative to that resource's body. The spelling in this
registry is the canonical wire spelling; clients must not invent underscore or
camel-case aliases.

| Type | Resource | When emitted | Delivery notes |
| --- | --- | --- | --- |
| `bead.created` | bead | A `create` operation commits. | Durable commit event; participates in every delivery class. |
| `bead.updated` | bead | A `patch` or `setMeta` operation changes a bead. | One event per changed resource; `setBy` identifies request or mutator ownership. |
| `bead.reparented` | bead | A `reparent` operation commits. | Closure and project changes appear in `changed`; derived closure rows follow in a derived changeset when fan-out is deferred. |
| `bead.linked` | bead | A `link` operation commits. | `changed` includes the typed edge; blocking edges bump `graph/blocking`. |
| `bead.unlinked` | bead | An `unlink` operation commits. | The `before` image contains the removed edge when readable. |
| `bead.commented` | bead | A `comment` operation commits. | Markdown is normalized before this event is written. |
| `bead.attached` | bead | An `attach` operation commits. | The event carries the attachment metadata; blob bytes are addressed by `contentRef`. |
| `bead.deleted` | bead | A `delete` operation commits. | The event is subject to current read authorization and redaction rules. |
| `bead.claimed` | bead | The `claim` or `claimNext` slot succeeds. | The lease is in the post-image; the lease itself is not a versioned record. |
| `bead.released` | bead | `bead.release` succeeds. | The event carries the release reason when the caller supplied one. |
| `bead.closed` | bead | The `close` slot reaches a completed/success status. | A close guard failure emits no event. |
| `bead.failed` | bead | The `fail` slot reaches a completed/failure status. | Failure is an outcome, not a generic error event. |
| `bead.canceled` | bead | The `cancel` slot succeeds. | The ontology decides whether the type exposes this slot. |
| `bead.reopened` | bead | The `reopen` slot succeeds. | The ontology decides the target status. |
| `bead.deferred` | bead | The `defer` slot succeeds. | The event carries the target project/status fields that changed. |
| `bead.lease.reclaimed` | bead | Lease reclaim removes an expired holder's claim. | The event is generated by the lease-reclaim job; its causal principal is `system:core`. |
| `gate.approved` | gate bead | `gate.approve` commits a distinct approval. | Duplicate sponsor-resolved human approvals produce no second approval event. |
| `gate.reported` | gate bead | `gate.report` accepts a resolver's state. | A resolved gate may cause a separate slot event. |
| `gate.escalated` | gate bead | A gate timeout escalates. | The last gate state remains `stale` until a resolver reports a new state. |
| `ontology.applied` | ontology | `ontology.apply` commits a planned revision. | This is a protected-record change and is always a policy/watch boundary. |
| `plugin.applied` | plugin set | `plugin.apply` commits a planned set/lock/config change. | The event is a policy/watch boundary; protected records cannot be changed by `tx.apply`. |
| `view.saved` | view | `view.save` creates or updates a saved view. | View watchers reset when the definition or version changes. |
| `view.deleted` | view | `view.delete` commits. | A watcher for the deleted view receives `watch.reset` with reason `view_deleted`. |
| `memory.saved` | memory | A memory record is created or updated. | Memory is a core record kind under P85. |
| `memory.deleted` | memory | A memory record is deleted. | The event follows ordinary read authorization and retention rules. |
| `sync.pushed` | sync destination | An outbound batch is accepted by a destination. | Destination telemetry is not a substitute for the bead changeset event. |
| `sync.imported` | sync destination | A one-shot import creates `import` changesets. | Each imported record's actual bead event is emitted in its own changeset. |
| `derived.updated` | derived record | A follow-up derived changeset updates readiness, closures, indexes, or sort keys. | Projections consume these in total order. `derived=true`. |

A successful `bead.heartbeat` renews an unversioned lease and returns no
revision, so it does not emit a durable bead event. A failed operation emits no
success event. `result.warnings` also do not create a second event.

## Control and delivery markers

These values use the same event envelope where a cursor or stream must carry a
boundary, but they do not represent a plugin-created graph mutation.

| Type | Meaning | Required details |
| --- | --- | --- |
| `event.gap` | The stream crosses a restore, failover, or a checkpoint below the available head. | `details.fromIncarnation`, `details.toIncarnation`, `details.floor`, and `details.reason`. The client must reopen/resume from the returned cursor. |
| `store.restored` | A dump restore completes and mints a new incarnation. | `details.fromIncarnation`, `details.toIncarnation`, and `details.reason: "restore"`; the envelope carries the new incarnation and old cursors cannot continue. |
| `watch.delta` | A coalesced snapshot-then-delta delivery frame. | `details.subscriptionId`, `details.fromCursor`, `details.toCursor`, and ordered `events`. It never reorders visible rows. |
| `watch.reset` | A watch must be rebuilt because policy, ontology, view membership, overflow, lag, or visibility changed. | `details.subscriptionId`, `details.reason`, and a new snapshot cursor. |
| `visibility.lost` | A resource that was previously visible is no longer readable under the current authorization chain. | `resource`, `details.reason`, and no readable `before`/`after` values. |
| `rpc.rejected` | A JSON-RPC notification was dropped because notifications cannot receive a result. | `details.requestId`, `details.reason`; WebSocket transports receive this server push. |

The control markers are filterable through `event.subscribe`'s `events` list.
A caller that does not request controls still receives `event.gap`, because it
is required to detect an invalid cursor and re-establish a safe stream.

## Canonical event union

`Event` is a tagged union in [`openrpc.json`](openrpc.json), not an open object.
Every frame has a `category` tag:

- `category: "durable"` selects a graph event and requires the durable envelope
  fields (`resource`, `changed`, `principal`, `chain`, `setBy`, `cause`).
- `category: "control"` selects one of the six control types above and
  requires its type-specific `details` object. Control frames never carry
  readable `before` or `after` images, and `derived` is always false.

The type/detail pairs are closed: `event.gap` uses `EventGapDetails`,
`watch.delta` uses `WatchDeltaDetails`, `watch.reset` uses `WatchResetDetails`,
`visibility.lost` uses `VisibilityLostDetails`, `rpc.rejected` uses
`RPCRejectedDetails`, and `store.restored` uses `StoreRestoredDetails`.
`watch.delta.details.events` contains the same `Event` union, so a coalesced
frame cannot smuggle an untyped event payload.

The Go model uses the same `Event` union with `DurableEvent` and
`ControlEvent` members and custom JSON marshal/unmarshal at the transport
boundary. A native plugin and a WASM plugin therefore see the flat OpenRPC
frame shown below; neither receives a Go wrapper containing a nested event
member.

The wire schemas require string members by presence and type without imposing
an additional minimum length. In particular, `visibility.lost.resource` is
required even when empty, and every other control type forbids that member.
Revisions, indexes and floors use the full nonnegative JSON integer domain;
`1.0` and `1e0` are integral spellings, and Go codecs preserve values beyond
machine integer ranges. `rpc.rejected.details.requestId` accepts a string or
an arbitrary-precision signed integer and must decode every supported ID that
its Go codec emits. `cause.depth` retains its maximum of 8.

## Event envelope

Every event frame delivered to a client has the tagged-union shape below.
Durable frames include the graph fields shown; control frames use their typed
`details` variant. Values that the caller cannot read are omitted; a durable
event may instead be replaced by `visibility.lost`.

```json
{
  "category": "durable",
  "cursor": "opaque",
  "incarnation": "store-incarnation-ulid",
  "revision": 812,
  "index": 0,
  "type": "bead.closed",
  "resource": "bead/pl-a3f",
  "changed": ["/status", "/closedAt"],
  "before": {"status": "in_progress"},
  "after": {"status": "done"},
  "principal": {"kind": "agent", "id": "agent:01..."},
  "chain": ["authz.team/default"],
  "setBy": {"status": "request"},
  "cause": {"root": "01...", "depth": 0, "chain": []},
  "derived": false
}
```

For example, a restore is a control frame rather than a durable graph event:

```json
{
  "category": "control",
  "cursor": "opaque-after-boundary",
  "incarnation": "new-incarnation-ulid",
  "revision": 0,
  "index": 0,
  "type": "store.restored",
  "details": {
    "fromIncarnation": "old-incarnation-ulid",
    "toIncarnation": "new-incarnation-ulid",
    "reason": "restore"
  },
  "derived": false
}
```

- `cursor` is opaque on JSON-RPC. Its decoded driver tuple is
  `{incarnation, revision, index}` plus the method, filter digest, principal
  digest, and ontology revision binding. The driver rejects a cursor whose
  incarnation differs from the current store before reading any revision;
  services map that boundary to `incarnation_changed`/`event.gap`.
- `revision` is the gapless changeset revision. `index` is the stable event
  order within that changeset. Consumers must preserve this order.
- `before` and `after` are materialized from the stored JSON Patch/base history
  and are masked by read policy. They are absent on a control marker and may be
  omitted on a minimal-return request. The OpenRPC tagged union rejects them on
  control frames.
- `principal` is stamped by transport authentication. `chain` records the
  authorization links that participated; it is empty when no authorization
  plugin is installed. `system:core` is used for invariant and derived work.
- `setBy` maps changed fields to `request` or a mutator/subscriber ID. It is
  part of the audit trail and never accepts arbitrary client text as a plugin
  event.
- `cause.root` identifies the originating request/change, `depth` is capped at
  8, and `cause.chain` records the causal plugin/listener path. A root write
  may cause at most 200 writes.
- `derived` is true for follow-up readiness/index/closure changesets. It does
  not mean that a plugin was allowed to bypass the normal write path.

`event.notify` wraps events for a subscription:

```json
{
  "subscriptionId": "sub-01...",
  "events": [/* Event */],
  "cursor": "opaque-after-last-event"
}
```

## Session lifecycle (decision #14)

`session.open` creates a caller-owned live session. Its idle expiry is at most
five minutes after opening or the latest successful `presence.set`; a
disconnect does not renew it. Expiry reclaims the session's presence, watches
and watch quota. One-shot CLI calls open no session.

`session.close {sessionId}` explicitly releases those resources and returns
`{closed: true}`. Unknown, expired, already closed or unreadable sessions
return `not_found`; authorization refusal returns `forbidden`. Closing a
session changes ephemeral collaboration state and produces no changeset.

After reconnect or failover, clients call `session.open` for a new session and
recreate watches with their last acknowledged cursors. They retain the cursor
expiry, reset and incarnation-gap rules above; reopening a session does not
make an invalid cursor usable.

## Delivery classes

| Class | Source and ordering | Failure, retry, and acknowledgement contract |
| --- | --- | --- |
| **Pull** (`event.list`) | Reads durable events after `after`, in cursor order. | A cursor below the retention/history floor returns `cursor_expired`; a different incarnation returns `incarnation_changed`/`event.gap`. No server-side acknowledgement. |
| **Subscription/watch** (`event.subscribe`, `view.watch`, `bead.watch`) | Snapshot first, then changeset deltas; a 250 ms coalescing window. Policy, ontology, view, overflow, or lag boundaries split/reset delivery. | At-least-once over a reconnect; clients acknowledge progress by resubmitting the last cursor. A session is capped at 32 watches. |
| **Post subscriber** | After commit and before the client answer; parallel per binding at the committed revision. | At least once through a binding checkpoint, key `{incarnation, revision, index, binding}`. Failure returns the committed result with `post_subscriber_failed`, dead-letters, alerts, and counts toward the breaker. Replays are marked `late`; idempotent side effects are required. |
| **Listener** | Asynchronous after commit, partitioned by resource ID. | At least once with the same binding key. Retries and dead-lettering are allowed; `event.subscription.skip` may skip a poison listener event after an audited admin action. |
| **Projection** | Asynchronous after commit, whole changesets in total order. | Failure halts the projection; it never skips an event. No skip operation is permitted. Rebuild from the log after repair. |
| **Audit** | Append-only authentication/denial/mutation audit alongside the changeset log. | Kept forever. Redaction reaches audit rows in its fixed closure; delivery checkpoints do not prune them. |
| **Control** | Restore/failover/gap/reset markers. | Must be delivered even when the requested filter has no matching graph resources, because clients need a safe cursor boundary. |

Checkpoint writes are themselves protected by the active storage lease epoch;
a deposed server cannot advance one. Listeners stall after seven days and
projections after thirty days, with operator alerts. Cursors therefore
coordinate delivery only: they never prune history, audit, or the changeset log.
