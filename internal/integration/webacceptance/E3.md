# E3 scripted browser recorder

This package records the five E3 questions on a disposable SQLite WAL store
containing exactly 20,000 actual beads and 50 simulated anonymous client labels.
It uses the actual Writer, service, collaboration manager, view operations,
RPC handlers, watch manager, NDJSON adapter, embedded UI and installed Chrome.
No human study is performed.

The corpus is deterministic: 200 Writer batches, 50 real sessions/claims,
50 initial updates, one real blocking edge, five real closes, then 50 updates
at the complete stored population. Claims are established on the first 100
beads before growing the corpus. A retained development run hit the unchanged
two-second Writer pre-phase deadline when claiming at full size; this fixture
does not certify full-size claim throughput. Driver enumeration checks every
stored ID/body and is independently cross-checked against physical SQL rows.

The connected fixture persists two resource-membership definitions and an
explicit readership grant in ordinary bead metadata via actual `tx.apply`.
Its test-only adapters read that metadata through `service.Get` and enforce
current resource/principal/project grants, denial and stored revocation. These
adapters do not implement production saved-view CRUD or an installed authz
plugin. Presence uses the real policy port; baseline ready reads retain their
admitted no-plugin behavior. No read policy is inferred from successful Get.

The five tasks each retain elapsed script time, browser observations, required
fields, missing fields, screenshot and actual wire references. `OBSERVED`
means the scoped observation ran; `BLOCKED`, `FAILED`, `TIMEOUT` and `NOT_RUN`
are preserved. A green Bazel recorder test does **not** mean E3 qualified.
In particular, readable direct blocker reasons, distinct anonymous agent
labels and epic parent/count paths are source dependencies, never synthetic
answers. Operational wait bounds are not usability thresholds.

Repeat from the exact isolated Plug checkout with Bazel 9.3.0, Docker, Node
and `google-chrome` installed:

```sh
E3_HEAD=$(git rev-parse HEAD)
E3_TREE=$(git rev-parse HEAD^{tree})
E3_EVIDENCE=/tmp/plug-swarm/ci-local/E3-repeat-$E3_HEAD
mkdir -p "$E3_EVIDENCE"
bazel --ignore_all_rc_files test //internal/integration/webacceptance:webacceptance_test \
  --disk_cache=/tmp/plug-swarm/bazel-disk-cache --local_resources=memory=8192 \
  --jobs=2 --lockfile_mode=error --cache_test_results=no --test_timeout=900 \
  --test_output=all --test_filter=TestE3ScriptedBrowserTaskReceipts \
  --test_env=PATH --test_env=PLUG_E3_SOURCE_HEAD="$E3_HEAD" \
  --test_env=PLUG_E3_SOURCE_TREE="$E3_TREE" \
  --test_env=PLUG_WEB_ACCEPTANCE_EVIDENCE_DIR="$E3_EVIDENCE"
bazel --ignore_all_rc_files shutdown
```

`e3/corpus-workload.json`, `stored-beads.jsonl`, `browser-outcomes.json`,
`browser-wire.json`, `harness-rpc.json`, `watch.ndjson`, policy receipts and
screenshots are the durable observations. If no evidence directory is set,
Bazel's undeclared outputs directory is used. TestMain also starts and removes
the existing disposable PostgreSQL engine for the historical regressions.
