# B14 default gates, listing, waits-for and history

The new acceptance uses actual ordinary composition and named JSON-RPC on
memory, SQLite and PostgreSQL. No gate catalog is seeded into the fresh host.
`bead.create` still requires its explicit type; await fields never select it.
The no-source runtime carries literal `gate`. Explicit stored catalogs remain
complete and authoritative, including refusal when they omit `gate`.

The ordinary and manual native targets independently assert default/all list
membership, templates before check limits, await filtering after limits,
timeout zero, exact ordered waiter replacement, and default/all/any waits-for
with `also_blocks`. Ready sets and close guards are checked through each
stage. Typed equal metadata conserves state; a changed child predicate changes
admission. Plug history retains earlier waiter/predicate images and each SQL
engine is physically closed/reopened without reseeding. Read requests and
responses plus physical rows/versions are retained as test outputs.

The default host also invokes actual ephemeral gate/workflow items on all
three engines. A joined public batch replaces durable and workflow waiter
lists and installs waits-for edges in both directions. Mixed listing merges
both planes before applying limits. The child/spawner stages assert the
independent all/any/also-blocks expectations, typed close refusals conserve
the complete stored image, and admitted closes retain each plane's status.
Memory asserts the selected capability's process lifetime and false
persistence marker; only SQLite and PostgreSQL run physical reopen. The
canonical native counterpart executes the same predicate stages with real
durable issues and ephemeral wisps, retaining its distinct close lifecycle.

The manual target builds the unchanged canonical 9d6 production CLI using the
existing B20 archive/manifest builder. Native writes use public CLI and HTTP;
SQL is read-only readback. Template gates come from actual formula cook. These
are public disposable fixtures; no private or official preparation is used.
Frozen A3 category differences are retained. There are no approval/CAS or
concurrent controls in this unit.

Fresh ordinary `ontology.schema` is actually not bound and is recorded as
`method_not_found`, without schema discovery credit. Formula/workflow behavior,
hosted delivery, native source-history import and full-card qualification are
distinct from ordinary history and paired current native behavior.

The gate-recognition importer port preserves explicit historical `gate` to
`issue` directives and their used accounting. Only the validated modern native
status/catalog route may preserve implicit literal gate; legacy and unrelated
unknown types still require their prior directives. Strict-union targets stay
authoritative. The parser controls are authored compatibility cases, not native
producer recordings or source-history import evidence.

All inherited B14 explicit installation/mapping/listing/member tests remain in
their original target and canonical whole. Their completed earlier receipts
are not borrowed by this candidate. The new focus target contains new cases
and shared fixture code, without selecting inherited completed tests.
