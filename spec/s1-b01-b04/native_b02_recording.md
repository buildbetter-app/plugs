# Private B02 native recorder

Done = the private recorder follows the canonical B02 native flow and preserves
complete real before/after, refusal, replay and producer evidence, proven by
its exact committed source and independent source review; B01 checker passes
and compilation alone do not count as B02 runtime.

This unit is SOURCE ONLY / AUTHORED_NOT_RUN. It grants no recording, dispatch,
whole-tree gate or collector authority. A future actual invocation of the
separate manual `native_b02_recording` target requires its own authorized
prepared-native scope. No runtime result is implied by the authored plan.

The source base is commit `7d1dd3911a08331ae537ddf154c9d9b2bac264ca`,
tree `23b0da7f989b15a7c808a57aae5425bb1518e824`, with sole parent
`5a92ea9f274c08d1116acac77aaa5946b6f73552` (parent tree
`eff755baa23d206b121f024100bec13c764e91a8`). The B02-only
`native_b02_inputs.json` binds that consumer lineage to the unchanged
accepted producer/control/helper/artifact tuple. The older `native_inputs.json`
remains the B01 consumer contract and is not reused as B02 provenance.
Preparation checks the four actual environment values, manifest bytes,
executable bytes, accepted source/tree, build run and linked version before
recording. The accepted producer source is
`c8eb3ba7d4177e111a6f5c8aebe06b5d0b1d5724`; its physical helper supplies the
actual private child environment and database roots. Each case/run owns a
fresh server and database, records physical identity, and stops its server.

The producer capability boundary is part of this input contract. The accepted
c8eb exporter refuses every nonempty `wisps`, `wisp_labels`,
`wisp_dependencies`, `wisp_events`, `wisp_comments` and `wisp_child_counters`
family; an `ephemeral` field retained on a durable issue is opaque source data,
not live workflow semantics. Its dependency allowlist is only `blocks`,
`parent-child`, `related` and `discovered-from`, so `waits-for`/gate metadata
and `conditional-blocks` have no accepted native archive route. The waits-for
and conditional plans therefore retain their actual native observations and
public replay separately, with no fabricated producer values. Nonempty
`custom_statuses`/`custom_types` are refused as well; the category plan keeps
the real native custom-status command and the expected dump refusal. These are
capability limits, not reasons to drop native plans or change the fixed
producer/control/helper pins.

The canonical card is B02 in `engdocs/design/plug/spec/behaviors/work.md`.

`blocked_recheck.go`, `create_deps.go` and `ready.go` determine the authored
native commands and explicit boundaries below. No historical recording is
used as a new observation.

There are seven plans, each recorded twice with fixed role IDs and separate
physical stores. The plan has 32 mutation/refusal steps plus seven initial
phases per run. All 78 primary native observations and both stale-case stable
rereads must complete before any Plug replay begins. Twins compare only the
declared semantic fields; the
original timestamps, revisions, command streams, database schemas and cells
are retained separately without normalization or replacement.

Every native command retains exact argv/environment, original stdout/stderr,
exit, time bounds and digests before assertions. A complete dynamic SQL census
enumerates every actual application table, its full DDL and all columns/rows,
plus the actual commit log and working status. Sorting whole rows supplies a
comparison representation; the original SQL streams stay intact. The census
runs before/after every action and before/after the public show, ready,
blocked and explanation sequence. It never drops a native table or column
because its spelling is inconvenient. Refusals must preserve this complete
image. Source row identities, parent/status/title, both native owner tables,
ready identities, blocked reason identities and explanation counts bind to
the actual native results. Native `--explain` ignores the ephemeral inclusion
flag in the accepted implementation; its own original output is retained,
while the explicit inclusive ready query controls mixed-plane membership.

The `also_blocks` step discovers its single actual stored dependency row and
updates metadata through the real SQL command. The stale case discovers the
actual owner row and changes only its stored flag, preserving `updated_at`.
Both requests, their affected-row counts, and complete before/after images
are retained. Neither seam is represented as a native product writer. The
stale case requires the flag to be false before the answering reads, true
after them, with the exact timestamp conserved, and requires a second whole
read sequence to conserve the repaired image. That stability does not prove
an internal nonrecursive call trace or a concurrent recheck schedule.

Five durable plans replay both actual captures independently on memory,
SQLite and PostgreSQL: 30 stores and 198 observed phases. There is no
ephemeral-to-durable substitution. Each Plug store uses a real public RPC
create and its returned refs, public links/unlinks with typed metadata, and
the configured lifecycle slots. Native open/closed-success/closed-failure
and canceled intent map explicitly to queued/finished/broken/abandoned;
native pinned/frozen map to backlog through the parked slot. Native custom
done remains a literal native status; it is not rewritten into native
closed. The raw public requests/responses remain originals.

Every accepted Plug write is bound to its completed method/key receipt and
whole returned Commit, conserves prior receipts and every non-target record,
then replays the exact same semantic request/key. The replay must return the
same complete Commit with response-only replay metadata and conserve all
state. A complete typed zero driver Changeset is recorded explicitly as
zero; all nonzero Changesets retain every field and the unchanged serializer.
Every read/refusal key must remain absent. A public transaction requesting a
title change followed by a missing-endpoint link must fail with no result and
conserve the full image; no internal staging point is inferred.

Full images retain every current record, complete bounded changeset history,
every version of every current record, all known completed receipts, all nine
derived tables and the graph-validity fact. The finite history must remain
strictly below the requested cap; truncation cannot count as closure. Reads
are bracketed by complete state snapshots. Full ready results must agree
with every one-row signed continuation, with unchanged actual snapshot
identity. Each SQL phase closes and reopens the physical store under a new
lease epoch between the first page and the remaining continuation. Active
fixture authority is renewed before each bracket, with no clock advance or
TTL/oracle relaxation.

The category plan also verifies the actual complete durable event plan.
Success/cancel must retain the ordinary lifecycle event and emit the one
condition-unmet notice anchored to the unchanged conditional dependent and
actual changed blocker revision; completed failure must emit no such notice.
This is authored public-core replay, not a claim of native event parity.

A successful empty pre-custom inventory/dump is kept as its own baseline.
Every final capture has a separate genuine public inventory with nonempty,
unique, regular, confined sidecar declarations and exact digest/size closure.
The custom-status case must retain the actual dump refusal
`unsupported nonempty family custom_statuses`, including absent/empty/partial
dump filesystem state. No status row is filtered to obtain a dump; no fake
import, restore or synthesized archive replaces it. Other final inventories
have no requested final dump; their baseline dump is not relabeled as a
post-mutation dump. Cleanup preserves complete output hashes and physical
helper receipts, excluding `poll.log` by basename before metadata or reads.

The mixed native chain, internal recheck trace, concurrent races, accepted
ephemeral Plug workflow production, native import/restore, public network
transport and hosted delivery remain explicit limits. The manual target has
not run at this source seal. FullB02 and FullB01 remain incomplete,
NativeAdmission=None and FullS1=0/28; existing B05 pause and historical REDs
are unaffected.
